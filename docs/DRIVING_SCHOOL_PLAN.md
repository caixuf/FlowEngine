# FlowEngine 驾校计划 — 科目一至科目四

> **状态：设计文档（实施完成后删除本文件）**
> 目标：让自动驾驶栈像人类学员一样通过驾校考试——每科有场景、有判定标准、有
> 扣分制评分、有 CI 门禁。"学会开车" = 全科 ≥90 分且持续不退步。
>
> 总原则（与项目铁律一致）：
> - **Python 仿真先行**：所有新场景先在 `tools/` 纯 Python 仿真里跑通+扫参，再动 C++
> - **模块职责分明**：仿真=被控对象（只积分物理），控制=唯一开车的人，规划=唯一决定去哪
> - **考试即门禁**：每科考试脚本可独立跑、可进 CI，不及格 = 阻断合并

## 第一期：科目二场地五项（本期核心）

### 为什么科目二最先做

科目二全是**低速 + 倒挡 + 满舵**工况——正是"掉头屁股横扫"bug 暴露的盲区：

| 现有盲区 | 科目二逼出它 |
|---------|-------------|
| steer 限幅钳在 [0.016, 0.16]，满舵 0.6 不可达 | 倒库/直角转弯必须满舵 |
| 倒挡路径跟踪从未测过（只有倒车速度限制） | 倒库/侧方全程倒挡 |
| 后轴零侧滑不变量只有单测，无场景级验证 | 压线判定直接暴露侧滑 |
| 低速 PID（<2m/s）从未标定 | 坡道定点要求 ±30cm 停准 |
| 无坡度物理（`step_bicycle` 无重力分量） | 坡道起步需要防溜车 |

### 新文件（唯一新增入口，不改 control_sim.py）

```
tools/subject2_sim.py        # 场地五项仿真+判定+扫参（纯 Python 标准库）
tools/driving_test.py        # 考试框架（第一期只挂科目二，后续挂三/一/四）
```

**复用 control_sim.py 的方式**：`from control_sim import VehicleState, stanley_control, ...`
（control_sim.py 是模块可 import；禁止复制粘贴第二份自行车模型——单一权威）

**需要对 control_sim.py 做的最小扩展**（三处，都是加参数不改行为）：
1. `VehicleState.step()` 加 `grade=0.0` 参数：`self.v += -9.81*sin(grade)*dt`（坡道重力分量，默认 0 不影响现有场景）
2. `VehicleState.step()` 的速度上限 `CRUISE_SPEED+2` 改为可选参数（科目二低速不受影响，保持默认）
3. 暴露 `STEER_FULL_LOCK = 0.60`常量（对应 entity.h steer_override=true 的物理限幅）

### 五项场景规格（判定标准 = 真实驾考标准的仿真化）

坐标约定：场地局部坐标，单位 m，车辆尺寸 4.6×2.0（与 straight_road.json 一致），轴距 2.7。

#### 1. 倒车入库 (reverse_parking)
- **场地**：库位宽 2.4（车宽+0.4，考试标准 1.5 倍车宽这里从严）、深 5.5；两侧库线；控制线距库 7.5
- **流程**：前进过控制线 → 倒挡右倒入库 → 停正 → 前出 → 左倒入库 → 停正
- **判定**：
  - 车轮压库线 → **不合格**（车身四角多边形与库线线段相交检测）
  - 中途停车 >2s → 扣 5 分/次
  - 车身入库后与库中线夹角 >5° → 扣 10（停不正）
  - 总时长 >210s → 不合格
- **暴露什么**：倒挡满舵路径跟踪、后轴运动学正确性（屁股先入库=正确物理！）

#### 2. 侧方停车 (parallel_parking)
- **场地**：库长 6.0（车长×1.3）、宽 2.4，右侧贴路沿
- **流程**：平行驶过库位 → 倒挡右打→左打 S 形入库 → 停正 → 打左灯前出
- **判定**：压库线/路沿不合格；中停 >2s 扣 5；出库不打灯扣 10；>90s 不合格
- **暴露什么**：倒挡 S 形（转向反打时机）、与倒库互补的左右对称性

#### 3. 坡道定点停车与起步 (hill_start)
- **场地**：坡度 10%（grade=atan(0.1)），坡长 20，定点桩在坡中
- **流程**：上坡 → 前保险杠对桩停车 → 停稳 ≥2s → 起步通过坡顶
- **判定**：
  - 停车点纵向偏差 >0.5m 不合格，>0.3m 扣 10
  - 起步后溜 >0.3m 不合格，>0.05m 扣 5（**关键指标：防溜坡**）
  - 起步超时 >30s 不合格
- **暴露什么**：低速 PID 精度、坡度重力补偿（现有 PID 无前馈必溜坡——预期先 FAIL，逼出坡道前馈）

#### 4. 曲线行驶/S弯 (s_curve)
- **场地**：两段相接的反向圆弧车道，半径 7.5、车道宽 3.5
- **判定**：任一车轮出车道边线不合格；中停 >2s 扣 5
- **暴露什么**：连续大曲率跟踪（κ=0.13，远超高速路的 0.005）、转向反打平顺性

#### 5. 直角转弯 (right_angle_turn)
- **场地**：两条宽 3.5 的垂直车道相接
- **流程**：直行 → 贴外侧 → 满舵直角转过 → 摆正
- **判定**：压角/压线不合格；中停扣 5；不打转向灯扣 10
- **暴露什么**：满舵时机决策（早打压内角、晚打出外线）——纯几何规划能力

### 通用判定基础设施（subject2_sim.py 内部）

```
car_polygon(state) -> 4 角点        # 车身多边形（含 heading 旋转）
poly_intersects_segment(poly, seg)  # 压线检测（每帧调用）
StopWatch                            # 中途停车计时（v<0.05 连续时长）
Scorecard                            # 扣分制记分卡：100 起步，逐项扣，输出明细
```

### 控制/规划层怎么开科目二的车（学员实现）

科目二不用 Stanley 巡航——用**几何路径 + 纯追踪(Pure Pursuit) + 倒挡镜像**：

1. 每项场景先离线生成参考路径（圆弧+直线拼接，倒库路径=两段圆弧对接）
2. 前进：Pure Pursuit（前视距离 = max(1.5, 0.5·v)）；倒挡：参考点换车尾、转向取反
3. 纵向：目标速度阶梯（直线 1.5 m/s，弯内 0.8，定点用距离-速度斜坡）
4. **参数扫描**（`--tune-s2`）：前视距离/满舵时机/入库起手位，各项独立扫

这层"学员"逻辑先活在 subject2_sim.py 里验证方法论；第二阶段才决定
哪些进 C++（预计：Pure Pursuit 倒挡跟踪 → control_node 的 maneuver 分支；
路径生成 → planning 的泊车 planner）。**本期不动 C++**。

